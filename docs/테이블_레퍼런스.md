# 테이블 레퍼런스 — customers · support_tickets · usage_monthly

이 테이블을 쓰기 전에 먼저 읽는 문서입니다. 숫자는 모두 edata9-data에서 SQL로 센 값입니다(2026-11-19 프로파일링).

## 한눈에

| 테이블 | 행 × 열 | 그레인 | 키 | 기간 | customers와 관계 | customers LEFT JOIN 행 수 |
|---|---|---|---|---|---|---|
| customers | 50,000 × 13 | 고객 1명 | customer_id (유일 50,000, null 0) | 가입 2018-12-25 ~ 2025-12-31, 해지 2025-01-01 ~ 2025-12-31 | — | 50,000 (자기 자신) |
| support_tickets | 32,789 × 10 | 문의 1건 | ticket_id (유일 32,789, null 0) | 2025-01-01 ~ 2025-12-31 | 1 : 0..N (최대 7) | **59,391** |
| usage_monthly | 523,825 × 9 | 고객 × 월 | (customer_id, year_month) (중복 0) | 2025-01 ~ 2025-12 | 1 : 0..N (최대 12) | **523,840** |

다른 테이블은 모두 `customer_id`로 customers에 붙습니다. 두 사실 테이블 모두 고아 키는 0개입니다. 고객 단위 지표를 낼 때는 **먼저 집계한 뒤 조인**해야 합니다. support_tickets와 usage_monthly를 집계하지 않고 함께 조인하면 행이 곱으로 불어납니다.

## customers

**그레인 · 키**
- 한 줄이 고객 1명입니다. `customer_id`는 C000001~C050000이고, 유일하며 null이 없습니다.
- `customer_name`은 고유값이 22,742개이고 같은 이름이 최대 9명이라, 식별자로 쓸 수 없습니다.

**기간**
- `signup_date`: 2018-12-25 ~ 2025-12-31로, 85개월 모두 있습니다. 월 중앙값은 601건이고, 2019-01~2024-11은 535~667건입니다.
  - **2024-12는 25건**입니다. 12-01에 10건, 12-02에 15건이고 **12-03~12-31은 0건**입니다.
  - **2025-01은 345건, 2025-02는 401건**으로 평소보다 적습니다.
  - 2018-12는 133건인데, 12-25부터 시작하는 부분월입니다.
- `churn_date`: 2025-01-01 ~ 2025-12-31, 7,256건입니다. 월별로 527~690건이고, **2025년 이전 해지는 0건**입니다.

**열**

| 열 | 형식 | null | 값 |
|---|---|---|---|
| acquisition_channel | VARCHAR | 0 | 검색 17,416 / 디스플레이 11,571 / 제휴 9,516 / 추천 7,460 / 오프라인 4,037 |
| plan_type | VARCHAR | 0 | LTE기본 13,781 / LTE무제한 12,404 / 5G스탠다드 10,953 / 알뜰 7,711 / 5G프리미엄 5,151 |
| monthly_fee | INTEGER | 0 | 요금제와 1:1 — 알뜰 19,000 / LTE기본 33,000 / LTE무제한 45,000 / 5G스탠다드 55,000 / 5G프리미엄 89,000 |
| age_group | VARCHAR | 0 | 30대 13,026 / 40대 12,064 / 20대 10,887 / 50대 9,029 / 60대이상 4,994 |
| region | VARCHAR | 0 | 17개 (경기 12,940 … 세종 461) |
| device_os | VARCHAR | 0 | Android 30,925 / iOS 19,075 |
| is_churned | BOOLEAN | 0 | true 7,256 / false 42,744 |
| churn_date | DATE | 42,744 | is_churned와 완전히 일치 |
| visitor_id | VARCHAR | **43,515** | 6,485개, 2025년 가입자에게만 있음 |
| campaign_id | VARCHAR | **43,515** | 120개, 2025년 가입자에게만 있음 |

**쓰면 안 되는 열과 이유**
- `campaign_id`, `visitor_id`
  - 87.0%가 null이고, 2025년 가입자 6,485명에게만 값이 있습니다.
  - 그 6,485명 중에서도 캠페인 기간 안에 가입한 사람은 **895명**뿐입니다. 시작 전에 가입한 사람이 3,254명, 종료 후에 가입한 사람이 2,336명입니다.
  - 따라서 캠페인 성과 분석에 그대로 쓸 수 없습니다.
- `is_churned`, `churn_date`를 장기 추이나 코호트 생존 분석에 쓰는 것
  - 해지는 2025년에만 있습니다.
  - 2019~2024년 가입 연도별 해지율은 15.0~16.1%로 평평하고, 2025년 가입자는 8.2%입니다.
  - 2025-01-01 기준 생존자만 남긴 스냅샷일 가능성이 있습니다.
- 가입 월별 추이에서 2024-12와 2025-01~02: 결측 구간으로 표시하거나 빼야 합니다.
- `customer_name`: 중복이 많습니다.

**데이터를 만든 사람에게 물을 것**
1. 2024-12-03~12-31 가입 0건, 2025-01~02 가입 감소는 수집 누락인가요, 실제 상황인가요?
2. 2025년 이전 해지자는 표에서 빠진 건가요, 해지 추적을 2025년부터 시작한 건가요?
3. campaign_id와 visitor_id가 2025년 가입자에게만 있는 이유는 무엇인가요? 캠페인 기간 밖 가입 5,590명에게는 어떤 기준으로 캠페인을 귀속했나요?
4. 오프라인 557명과 추천 1,385명에게 붙은 캠페인 ID는 무엇을 뜻하나요?
5. monthly_fee는 정가인가요, 실청구액인가요? plan_type, region, device_os는 가입 시점 값인가요, 추출 시점 값인가요?

## support_tickets

**그레인 · 키**
- 한 줄이 문의 1건입니다. `ticket_id`는 T000001~T032789로 빈 번호가 없고, 유일하며 null이 없습니다.
- `(customer_id, created_date)`는 중복이 40건 있어서 키로 쓸 수 없습니다.
- 문의한 고객은 23,398명입니다. 고객당 문의 수는 최소 1, 평균 1.40, 최대 7입니다.
- `agent_id`는 120개로, agents 테이블 120행과 같습니다.

**기간**
- `created_date`: 2025-01-01 ~ 2025-12-31로, 365일이 모두 있습니다. 날짜 열은 이것 하나뿐입니다.
- 월 건수는 2,539(2월)~2,883(12월)이고, 일평균은 85.0~93.0입니다. 빠진 달이나 크게 적은 달은 없습니다.
- 요일별 건수는 4,613~4,792로, 주말과 평일이 같습니다.

**열**: 모든 열에서 null 0, 빈 문자열 0입니다.

| 열 | 값 |
|---|---|
| contact_channel | 전화 14,324 / 챗봇 7,967 / 앱 6,865 / 이메일 3,633 |
| ticket_category | 요금 10,166 / 품질 7,794 / 가입변경 6,220 / 기타 4,349 / 해지 4,260 |
| status | 완료 29,772 / 진행중 2,002 / 보류 1,015 |
| is_recontact | false 25,362 / true 7,427 |
| duration_min | 1 ~ 80, 평균 13.27 |
| resolution_hours | 0.2 ~ 97.1, 평균 14.41 |

**조인**
- customers에 없는 키는 0개입니다. 문의가 없는 고객은 26,602명입니다.
- customers LEFT JOIN 결과는 **59,391행**입니다(26,602 + 32,789).

**쓰면 안 되는 열과 이유**
- `resolution_hours`
  - 진행중·보류 3,017건 전부에 값이 있고, 분포가 완료 건과 같습니다.
  - 상담 시간보다 짧은 행이 68건 있습니다.
- `status`
  - 미완료 비율이 접수 월과 상관없이 매달 7.8~10.0%입니다.
  - 그래서 백로그 분석에는 쓸 수 없습니다.
- `is_recontact`
  - true 7,427건 중 5,339건은 그 고객의 첫 문의이고, 3,603건은 그 고객의 유일한 문의입니다.
  - 직전 문의가 7일 안에 있었던 경우는 true 쪽 115건, false 쪽 385건입니다.
- 채널 비교에 쓰는 `duration_min`, 챗봇 행의 `agent_id`
  - 채널별 평균이 13.24~13.34로 같고, 챗봇에도 상담원 120명이 모두 배정돼 있습니다.
- `ticket_category = '해지'`를 이탈 신호로 쓰는 것
  - 해지 문의 4,260건 중 3,911건은 고객이 이탈하지 않았습니다.
  - 해지 문의가 있는 고객의 이탈률은 8.3%로, 문의가 없는 고객의 19.2%보다 낮습니다.

**데이터를 만든 사람에게 물을 것**
1. resolution_hours는 무엇을 잰 값인가요? 미완료 3,017건에 값이 있는 이유와, 상담 시간보다 짧은 68건이 생긴 이유는 무엇인가요?
2. status는 언제 기준의 상태인가요? 1월에 접수된 진행중 168건이 연말에도 진행중인가요?
3. is_recontact의 정의는 무엇인가요(기간, 같은 이슈 여부, 2025년 이전 이력 포함 여부)?
4. 이메일·챗봇의 duration_min은 무엇인가요? 챗봇 문의에 상담원이 배정된 이유는 무엇인가요? 주말 문의량이 평일과 같은 게 맞나요?
5. '해지' 카테고리는 해지 요청인가요, 해지 관련 문의 전반인가요? 같은 고객·같은 날 40쌍은 중복인가요?

## usage_monthly

**그레인 · 키**
- 한 줄이 고객 × 월입니다. `(customer_id, year_month)`가 523,825개로 행 수와 같습니다.
- `year_month`는 'YYYY-MM' 형식의 VARCHAR이고, 형식이 어긋난 행은 0입니다.
- 고객은 49,985명이고, 고객당 1~12개월(평균 10.48)입니다. 12개월이 모두 있는 고객은 37,630명입니다.
- 고객 안에서 중간에 빠진 달은 0입니다. 가입월 이전 행과 해지월 이후 행도 0입니다.

**기간**
- 2025-01 ~ 2025-12로, 월 43,412~43,845행입니다. 빠진 달이나 작은 달은 없고, 완만하게 줄어듭니다.

**열**: 모든 열에서 null 0입니다.

| 열 | 형식 | 범위 / 값 |
|---|---|---|
| data_gb | DOUBLE | 0.23 ~ 128.27 |
| voice_min | BIGINT | 55 ~ 239 (0분인 달 없음) |
| sms_count | BIGINT | 0 ~ 32 |
| billing_amount | INTEGER | 10,450 ~ 100,480 |
| app_login_count | INTEGER | 0 ~ 36 |
| service_count | BIGINT | 0 ~ 12 (0이 47,425행) |
| is_active | BOOLEAN | **TRUE 523,825 / FALSE 0** |

**조인**
- customers에 없는 키는 0개입니다.
- 사용량 행이 없는 고객은 15명입니다. 15명 모두 해지 고객이고, churn_date가 2025-01-01입니다.
- customers LEFT JOIN 결과는 **523,840행**입니다(523,825 + 15).

**쓰면 안 되는 열과 이유**
- `is_active`: 100% TRUE이고, 해지월 7,016행도 TRUE입니다. 해지 여부는 `customers.churn_date`로 판단해야 합니다.
- `billing_amount`를 매출로 쓰는 것
  - 465,995행(약 88%)이 monthly_fee보다 작습니다.
  - 하한이 정확히 monthly_fee × 0.55입니다.
  - 정가를 넘는 행과 넘지 않는 행의 사용량이 같습니다.
- `service_count`: 0인 47,425행 모두 데이터와 통화 사용량이 있고, 다른 열과의 상관이 0입니다.
- 해지월·가입월 행을 한 달 사용량으로 비교하는 것
  - 일할 계산이 되어 있지 않습니다. 해지일이 1~10일이든 21~31일이든 평균이 16.17 GB와 15.75 GB로 거의 같습니다.
  - 해지일이 1일인 225명은 해지월 행이 없습니다.
- `voice_min`: 요금제별 평균이 90.1 / 120.0 / 140.0 / 150.0 / 180.0으로 거의 정수입니다. 생성한 값으로 보입니다.

**데이터를 만든 사람에게 물을 것**
1. is_active가 전부 TRUE인 이유는 무엇인가요? 비활성 월은 행을 만들지 않은 건가요?
2. billing_amount는 할인 후 청구액인가요? 0.55배 하한과, 정가를 넘는 66,214행에 더해진 것은 무엇인가요?
3. 해지월·가입월을 일할 계산하지 않은 것은 의도인가요? 1일에 해지한 고객의 해지월 행을 빼는 규칙이 맞나요?
4. service_count는 무엇을 센 값인가요?
5. 요금제별 데이터 한도가 있나요? voice_min은 생성한 값인가요?

## 분석 전에 알아 둘 것

1. 세 테이블이 겹치는 기간은 **2025년 한 해뿐**입니다. 해지도 2025년에만 있어서, 장기 해지 추이나 코호트 생존 분석은 할 수 없습니다.
2. customers에 사실 테이블을 붙일 때는 **먼저 고객 단위로 집계**해야 합니다. 그대로 붙이면 59,391행이나 523,840행으로 불어나고, INNER JOIN을 하면 고객이 빠집니다(usage만 붙여도 15명이 빠짐).
3. 이름과 값이 다른 열은 정의를 확인하기 전까지 쓰지 않습니다. `is_active`, `status`, `resolution_hours`, `is_recontact`, `service_count`, `billing_amount`(매출로 쓰는 경우), `campaign_id`가 해당합니다.
4. 가입 월별 추이에서 2024-12(25건)와 2025-01~02는 결측 구간으로 표시해야 합니다.
5. 채널·카테고리·요일별 수치가 거의 같아 합성 데이터로 보입니다. 차이가 작으면 그 차이를 결론으로 삼지 않습니다.
